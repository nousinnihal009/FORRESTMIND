# Completing ForestMind

Updated October 20, 2026 for **v0.6.0**. The bounded local monitoring application is implemented and undergoing final acceptance verification. The full ecological early-warning proposal is not complete. Software behavior, deployment readiness and scientific predictive validity have separate acceptance gates.

## Three acceptance gates

| Gate | Current state | Evidence still required to close the gate |
| --- | --- | --- |
| **G1 — Working local application** | Worldwide place search, confirmed small AOIs, actual collection, durable jobs, saved evidence, connected analysis and local refresh/schedules are integrated. Real acquisitions and context collection have succeeded. | Finish the current mobile/keyboard/export browser checks, final regression and package verification; record exact results in `VALIDATION.md`. Acceptance applies to the documented bounded local workflow, not every original research capability. |
| **G2 — Operational deployment** | Local-only access controls, migrations, health diagnostics, job recovery, quotas, verified backups, restore tests and an operator rollback guide are implemented. | Hosted authentication, authorization and area/job ownership isolation; production supervision, retention, load/failure and access tests; deployment/rollback drill. Optional webhook delivery still needs an explicitly authorized real receiver and delivery verification. No public deployment or external delivery has occurred. |
| **G3 — Scientific predictive validity** | **Not achieved.** Research architectures, eligibility checks and a reference-experiment harness exist; the development training/evaluation examples are synthetic. | Independent real reference labels, protected geographic/temporal experiments, compatible real-trained models, separate calibration, useful warning performance and regional transfer evidence. Causal intervention and irreversible tipping-point claims require additional study designs and evidence. |

## What v0.6 now provides

The dashboard supports explicit attributed place search, coordinate/map selection and exact boundary confirmation. Sentinel-2 collection freezes its plan, bounds downloads and storage, records quality failures and gaps, and preserves accepted observations across cancellation, resume and restart. Saved areas can refresh and run local schedules while the service is running.

Connected analysis retains immutable geometry, observation cutoff, accepted source hashes, method/context/model versions and exports. It computes measured optical change, eligible baseline forecasts, seasonal recovery diagnostics and classified-cover topology. Actual ERA5 climate, dated ESA WorldCover and matched Sentinel-1 RTC pairs can be collected as context. These layers are not silently treated as trained neural inputs. Five-year comparisons are explicit hypothetical indicator sensitivities. Alert thresholds, supporting observations, review notes and lifecycle controls remain separate from ingestion/freshness failures.

The real Tapajós browser pilot began with two accepted observations; a subsequent bounded refresh/cancel/resume exercise added two more. The saved Tamil Nadu area retains its one actual observation, and an additional Germany pilot has one. Actual climate, WorldCover and radar context have also been collected, and saved areas/context survived restart. These checks demonstrate provider and application paths across several locations; they do not establish sufficient time series or worldwide ecological transfer. Earlier one-scene and eight-month imports remain preserved. A full database/source/workflow backup was created and verified. Final browser and regression evidence is still being consolidated in [VALIDATION.md](VALIDATION.md).

## Remaining work, with dependencies separated

| Workstream | Remaining implementation | External or scientific dependency and acceptance evidence |
| --- | --- | --- |
| Observation coverage and alignment | Seasonal radar histories and optical/radar neural alignment; harmonized Landsat acquisition through the UI; automatic fire/burned-area and human-activity histories; comparable multiepoch forest-loss classification. Defined climate anomaly/extreme/drought computations also remain incomplete. | Suitable licensed products, temporal coverage and justified climatologies/quality rules. Verify actual aligned acquisitions and preserve gaps, source semantics and native-resolution limits. |
| Native pretrained execution | Audited architecture-only native construction, complete strict local checkpoint loading, modality-specific preprocessing and a verified offline execution path. The normal workflow currently rejects unsupported native, synthetic and incompatible models. | Exact licensed Prithvi/TerraMind artifacts, a compatible pinned runtime, complete trained ForestMind heads and measured offline forward-pass evidence. TerraTorch and the native checkpoints are absent locally. RTC context must not be relabeled as GRD input. See [NATIVE_MODEL_AUDIT.md](NATIVE_MODEL_AUDIT.md). |
| Controlled model comparisons | Extend the existing persistence/seasonal/regularized/random-forest harness into a common boosted/recurrent/pretrained/multimodal/resilience-ablation comparison. Learned multimodal input preparation is incomplete. | A versioned independent label dataset with uncertainty, fixed outcome/horizons, protected buffered geographic splits and temporal embargo. Run every model on identical held-out examples; retain negative results. CPU-only execution limits scale; no paid compute has been provisioned. |
| Useful forecasts and alerts | Trained five-year ecological projections and calibrated spatial future-risk maps are absent. Existing area-level baselines, sensitivity curves and event/calibration metrics do not supply those models. | Independent future outcomes, separate calibration data, justified decision thresholds and response costs. Measure errors, calibration, false/missed events, warning lead time, subgroup performance and transfer before accepting predictive claims. |
| Ecological mechanisms and interventions | Species-specific connectivity, road/frontier loss, patrol/corridor/regeneration mechanisms and causal or process-based intervention simulation remain incomplete. | Field/reference observations, intervention/comparison data or validated process models. General pressure/restoration sliders remain sensitivity assumptions until those effects are established. |
| Hosted operation | Multi-user identity and ownership enforcement, production service supervision, retention/capacity policy and deployment controls remain separate work. | Intended users, hosting/account decisions and operational acceptance criteria. Demonstrate isolation, recovery, restore/rollback and authorized notification delivery before public operation. |

These are missing implementations and evidence dependencies, not completed features represented by unavailable-capability cards. The item-by-item scope is maintained in [REQUIREMENTS_MATRIX.md](REQUIREMENTS_MATRIX.md).

## Next scientific milestone

Freeze one measurable disturbance or degradation outcome, its intended use, forecast horizon, reference source, uncertainty rules and evaluation protocol before tuning. Acquire a sufficiently long, quality-checked history and independently review the reference labels. Use the existing experiment harness to establish conventional baselines, then compare any eligible pretrained or multimodal model on the same protected examples. Broaden geography or model complexity only when the held-out evidence supports it.

Predicting an indicator anomaly, detecting clearing, attributing a driver, estimating resilience statistics and establishing an irreversible ecological tipping point are different claims. Passing tests or producing a map does not establish any stronger claim. See [RESEARCH_PROTOCOL.md](RESEARCH_PROTOCOL.md) for experimental controls and [OPERATOR_GUIDE.md](OPERATOR_GUIDE.md) for local setup, limits, recovery and rollback.
