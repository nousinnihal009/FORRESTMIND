# ForestMind proposal and acceptance traceability

Reviewed against the original 17-section proposal and the expanded worldwide-monitoring request on 2026-10-19. This matrix records **software implementation**, **verification**, and **scientific evidence separately**. A capability card explaining missing evidence is useful interface behavior but is not completion of the underlying research capability. Existing synthetic tests exercise contracts only. See `VALIDATION.md` for executed commands, browser records and real-provider artifacts; this document never converts a planned test into a passed test.

Status vocabulary: **Implemented** means executable application computation; **partial** identifies the remaining implementation explicitly; **research** requires independently labeled observations/experimental evidence; **blocked** names an external dependency. “Test” below is the acceptance check and, where named, its automated test source. A script alone is not the normal monitoring workflow.

Provider availability and sufficient per-area history remain conditional. |
| G2 Operational deployment | Authentication, ownership isolation, migrations, backup/restore, service supervision, security/retention, load/failure tests and documented rollback | Local-only controls and operating artifacts are implemented/being verified. Hosted multi-user identity, ownership isolation and production deployment are **not** established; do not publish the unauthenticated service. |

No causal-intervention or irreversible tipping-point claim is established. |

## Exact evidence dependencies that still prevent the full proposal

1. **Real references and protected experiments:** no independent longitudinal forest-condition/driver/future-event reference dataset or operator-approved protected geographic/temporal split has been supplied. This prevents model training/acceptance, calibration, geographic transfer, false-alert/lead-time and ecological recovery claims. An experiment harness can verify data contracts, but cannot create the missing evidence.
2. **Compatible operational models:** the supplied development checkpoint was trained on synthetic data. Normal monitoring rejects it. Native TerraMind/Prithvi inference needs an authenticated local weight artifact, applicable license/input configuration, verified offline construction and held-out acceptance. CPU execution limits experiment size; no paid compute has been provisioned.
3. **Remaining data integrations:** selected-area same-orbit RTC pairs, ERA5 climate context and WorldCover historical classifications are now collected through the application. Long seasonal radar histories and neural modality alignment remain incomplete. Automatic fire products, human-activity histories, harmonized Landsat UI histories and comparable multiepoch forest-loss classification are incomplete. A layer being contextual does not make the neural model multimodal.
4. **Spatial future prediction and ecological mechanisms:** area-level trajectory heads do not produce calibrated per-pixel future-risk probabilities. Species-specific connectivity, road/frontier loss, patrol/corridor/regeneration mechanisms and causal/process intervention simulation need both implementation and independently validated inputs.
5. **Hosting:** public identity, user ownership/isolation, production hosting supervision, load testing and authorized notification delivery are separate deployment work. The local service must not be exposed as an unauthenticated public service.

These are explicit remaining work items, not completed capabilities disguised as unavailable panels. The working local workflow and honest evidence diagnostics advance the software milestone; they do not close the original scientific proposal.
