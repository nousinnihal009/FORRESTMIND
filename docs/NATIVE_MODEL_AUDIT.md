# Native encoder loading audit

Audit date: October 20, 2026. Native Prithvi/TerraMind inference remains unavailable in the monitoring application and offline inference command. The existing development checkpoint is a small `custom_vit` trained on synthetic observations. Correcting registry identifiers does not convert it into a pretrained or validated forest model.

## Verified local state

The active Python environment has PyTorch 2.10.0 and torchvision 0.25.0. TerraTorch, timm, transformers, safetensors and huggingface_hub are absent. The repository's `foundation` optional dependency group specifies lower bounds rather than an experimentally verified runtime lock. No native Prithvi or TerraMind checkpoint was found in this project; the three files under `checkpoints/quick_test/` belong to the synthetic development run. `best_model.pt` was inspected with `torch.load(..., weights_only=True)` and declares `foundation.name: custom_vit` and `data.source: synthetic`.

Both native adapters currently call `BACKBONE_REGISTRY.build(..., pretrained=True)`. That path may request remote weights. `predict_checkpoint` rejects it before model construction and before input loading. The automatic workflow also requires an eligible operator-reviewed real-model registry record. These gates remain intact. A nonboolean `use_proxy` field is rejected, so strings such as `"false"` cannot silently choose a development proxy.

`configs/default.yaml` now uses the documented registry identifiers `prithvi_eo_v2_300` and `terramind_v1_base`, with explicit `use_proxy: false`. The default selected encoder remains `custom_vit`. Choosing either native encoder for research training still requires its actual runtime and weights; the config is not a claim that native execution was tested.

## What the upstream implementation establishes

The official Prithvi builder supports architecture construction without weights using `pretrained=False`. In the source reviewed, `ckpt_path` loading occurs under `pretrained=True` and uses a checkpoint filter followed by a non-strict state load. Merely passing a local path therefore would not establish ForestMind's requirement that every expected trained parameter is present. [Official Prithvi registry source](https://github.com/torchgeo/terratorch/blob/main/terratorch/models/backbones/prithvi_vit.py).

TerraMind similarly exposes architecture-only construction and local checkpoint loading. Its local path uses a non-strict load; other model variants can initialize tokenizers or generators. A verified integration must constrain the exact architecture and observed modalities, and separately verify every retained state entry. A generic registry name or successful constructor is insufficient. [Official TerraMind registry source](https://github.com/torchgeo/terratorch/blob/main/terratorch/models/backbones/terramind/model/terramind_register.py).

The documented native TerraMind encoder accepts separately named inputs, including `S2L2A`, `S1GRD` and `S1RTC`, and returns layer token tensors. ForestMind's current adapter names its SAR input `S1GRD`; the new contextual radar collector reads RTC gamma-naught power. Those products must not be interchanged merely because both have VV/VH channels. The context collector deliberately remains outside model inputs. [Official TerraMind guide](https://github.com/torchgeo/terratorch/blob/main/docs/guide/terramind.md).

These sources describe upstream interfaces, not an installed or tested native runtime. Their mutable `main` references must be replaced by the exact tested release/commit in an eventual model manifest.

## Required implementation and evidence before enabling inference

1. Build an isolated native-model environment, resolve TerraTorch and its full dependency graph, verify imports on the target platform, then save exact versions and hashes. The broad `foundation` extra alone is not a reproducible environment. The provider's dependency manifest is the starting point, not evidence of compatibility with this machine. [TerraTorch dependency manifest](https://github.com/torchgeo/terratorch/blob/main/pyproject.toml).
2. Obtain the exact licensed native encoder artifact and a complete ForestMind checkpoint containing the trained projection, fusion, temporal and task-head state. A generic pretrained encoder alone has no trained ForestMind health, driver or trajectory heads. Record provider revision, artifact digest, licensing, training sources, target definitions and evaluation provenance.
3. Add a distinct architecture-only constructor path that passes `pretrained=False`, permits only audited model variants and modality options, and does not request a tokenizer, generator, download or proxy fallback. Load the entire ForestMind state with `weights_only=True` and `strict=True`. Reject absent, extra, incompatible or nonfinite parameters instead of accepting a partially random model.
4. Validate physical band order, units, normalization exactly once, pixel spacing, spatial grid, timestamp interpretation, missing-modality policy and masks against the checkpoint's training contract. Prithvi's selected Sentinel bands are not evidence that an HLS-trained encoder transfers unchanged. RTC input requires an RTC-compatible model contract and paired observed sequences, rather than relabeling the existing GRD stream.
5. With networking disabled and caches empty, exercise an actual native constructor, complete local state load and repeatable forward pass on measured inputs. Capture output shapes, memory/time bounds and dependency/model hashes. Test missing weights, corrupted state and attempted downloads. Only then extend the offline command and automatic workflow allowlist; independently validate held-out predictive performance before approving operational model results.

The inference and adapter regression suite passed **83 tests in 12.84 seconds** on October 20, 2026. The default YAML parsed successfully, with both corrected registry IDs and explicit native flags verified. The local tests confirm that both native choices fail before download-capable construction and that explicit proxy selection is type-checked. They do not test real native weights, native offline construction, pretrained representations or ecological accuracy. No native package or multi-gigabyte checkpoint was installed during this audit, and no operational model gate was weakened.
